# Архитектура изолированного payload SMLogix для сборки

## Назначение

Изолированный payload SMLogix предназначен для CLI-компоновки PSL в LFS через
локальную копию файлов SMLogix. Такой режим позволяет выполнять сборку через
Loader независимо от запущенного основного экземпляра IDE и после предварительной
синхронизации сохраняет сборочный контур внутри папки Loader.

Пользователь выбирает метод сборки в настройках:

- `Основной` - сборка использует установленный SMLogix.
- `Изолированный` - сборка использует синхронизированный payload из папки Loader.

## Расположение

Payload хранится рядом с опубликованным Loader:

```text
SMLogix isolated payload/
```

Основные элементы payload:

- `SMLogix/` - выбранный набор файлов из каталога установки SMLogix.
- `ini/` - выбранный набор файлов из каталога настроек SMLogix.
- `SMLogix7za.exe` - отдельная корневая копия архиватора для сценариев сборки.
- `fake-plc-software-versions.json` - профиль версий для изолированного fake PLC.
- `manifest.json` - описание синхронизированного состояния.

## Синхронизация

Синхронизация запускается из окна настроек кнопкой рядом с методом
`Изолированный`.

Процесс синхронизации:

1. Loader находит установленный SMLogix и каталог его настроек.
2. Строится актуальный manifest по выбранным файлам каталога установки и `ini`.
3. Manifest сравнивается с текущим `SMLogix isolated payload/manifest.json`.
4. При необходимости Loader обновляет локальную копию payload.
5. Из `Linux_Kernel/firmware.frw` установленного SMLogix извлекается профиль
   версий и сохраняется в `fake-plc-software-versions.json`.
6. Записывается новый `manifest.json`.

Manifest фиксирует:

- путь исходной установки SMLogix;
- путь исходного каталога `ini`;
- длину и время изменения файла прошивки, из которого получен профиль версий;
- список файлов payload с длиной и временем изменения.

## Использование при сборке

В режиме `Основной` Loader запускает CLI из установленного SMLogix.

В режиме `Изолированный` Loader запускает:

```text
SMLogix isolated payload/SMLogix/SMLogix.exe
```

Для изолированной сборки используются:

- локальная копия `SMLogix/`;
- локальная копия `ini/`;
- `fake-plc-software-versions.json`;
- встроенный .NET fake PLC;
- process-local native redirector и DHCP stub.

Process-local virtualization применяется внутри запускаемого процесса SMLogix и
его дочерних процессов. Глобальные параметры установленного SMLogix и системный
реестр этим сценарием не изменяются.

Redirector виртуализирует значения реестра SMLogix:

- `PATH_INSTALL` указывает на `SMLogix isolated payload/SMLogix/`;
- `PATH_INI` указывает на `SMLogix isolated payload/ini/`.

После успешной синхронизации изолированная сборка должна работать без
установленного SMLogix IDE.

## Связь с обновлением ядра

Изолированный payload обслуживает только сборку PSL в LFS.

Обновление ядра использует профиль и файлы прошивки из выбранного пользователем
или стандартного firmware-источника. Во время синхронизации из `Linux_Kernel`
берётся только профиль версий для fake PLC.

## Список исключений

Исключаемые корневые папки:

- `2G_Kernel`
- `2Gi_Kernel`
- `ADS_Toolkit`
- `Airport`
- `EK`
- `Linux_Kernel`
- `PIC`
- `PixelArt`
- `Pixel_Kernel`

Исключаемые корневые файлы:

- `help_en.chm`
- `help_ru.chm`
- `help_RU.chw`
- `Uninstall.exe`
- `UpdateChecker.exe`
