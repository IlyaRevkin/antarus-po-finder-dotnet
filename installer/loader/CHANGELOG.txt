Segnetics Loader - история изменений

Версия 2.8.9
- В Automation CLI добавлена проверка связи с ПЛК через команду --check-connection и действие checkConnection. Проверка использует сохранённые настройки Loader и общий DHCP/SSH-пайплайн.

Версия 2.8.8
- Обновлены библиотеки SSH, SQLite и тестовой инфраструктуры; устранены предупреждения NuGet об известных уязвимостях.

Версия 2.8.7
- Интерфейс Loader и Automation API переведены на единый сценарий форматирования проекта, обновления ядра и восстановления подключения к ПЛК.
- Исправлено обновление ядра через выбранный USB/RNDIS-адаптер при переинициализации сети и одновременном подключении нескольких ПЛК.
- Устранены зависания recovery при повторных DHCP/TFTP-запросах и ожидании ПЛК после перезагрузки.
- Внешние служебные процессы Loader теперь завершаются вместе со всем деревом дочерних процессов.

Версия 2.8.6
- Исправлено USB-подключение к ПЛК при наличии нескольких сетевых адаптеров в одной подсети: DHCP, SSH и загрузка выполняются через выбранный USB/RNDIS-адаптер.

Версия 2.8.5
- Улучшено отображение обновления программных модулей и ожидания готовности ПЛК по SSH после обновления ядра.
- Уточнено итоговое сообщение об успешной загрузке LFS-проекта.

Версия 2.8.4
- Automation API сохраняет собранный LFS после успешной загрузки PSL-проекта.

Версия 2.8.3
- Служебные сообщения сборки PSL через SMLogix в интерфейсе Loader и Automation API переведены на русский язык.

Версия 2.8.2
- В Automation API добавлена отдельная сборка PSL-проектов в LFS через изолированный SMLogix без подключения к ПЛК.

Версия 2.8.1
- В Automation API добавлен сценарий форматирования проекта и обновления ядра перед загрузкой.
- После обновления ядра Loader ожидает окончательную загрузку ПЛК до трёх минут и не запускает recovery повторно после подтверждённого завершения обновления.

Версия 2.8.0
- Добавлено безопасное переключение активного профиля проекта ПЛК при загрузке LFS и форматировании.
- При ошибке переключения Loader восстанавливает предыдущие файлы проекта и базу настроек из резервной копии, созданной перед началом операции.
- Информация о проекте на ПЛК теперь учитывает фактически активный профиль и не принимает неактивные metadata за работающий проект.

Версия 2.7.0
- Добавлен JSONL Automation API для фонового запуска сборки и загрузки проектов из внешних приложений. Вызывающее приложение получает прогресс, логи, итоговый статус и может отменить операцию.
- Интерфейс Loader и Automation API используют общий сценарий определения подключения к ПЛК, сборки и загрузки проектов с общей блокировкой параллельных операций.
- Добавлена автоматическая проверка файлов изолированного SMLogix при запуске Loader и CLI.
- Добавлено чтение runtime metadata ELF: в информации о проекте отображаются архитектура companion/native, целевая платформа и использование экрана.
- ELF-компонент ZOP всегда загружается в companion-режиме независимо от настройки метода загрузки отдельных ELF-файлов.

Версия 2.6.0
- В настройки добавлен изолированный режим сборки проектов. Файлы SMLogix, необходимые для сборки, копируются в папку Loader, после чего сборка через Loader запускается в изолированной среде и не мешает работе установленного SMLogix.

Версия 2.5.6
- Проекты SMLogix в отладочной компоновке теперь можно собирать без ручного пересохранения в рабочей компоновке. Тип компоновки исходного файла не меняется.

Версия 2.5.5
- Фикс поведения окна при докинге.

Версия 2.5.4
- Добавлено отображение описания изменений в диалоге автообновления.
- Добавлено управление ассоциациями файлов .lfs и .zop в настройках приложения.
- При выборе готового файла .lfs, .zop или ELF предварительная сборка автоматически отключается.

Версия 2.5.3
- Разделена информация о загруженном PSL/LFS проекте и ELF/ZOP бинарнике при чтении состояния ПЛК.
- Форматирование проекта теперь очищает metadata только выбранной части: PSL/LFS или ELF/ZOP.

Версия 2.5.2
- Исправлен поиск и запуск автообновления для архивов на сетевых дисках

Версия 2.5.1
- Автообновление перед поиском архива проверяет доступность каталога обновлений; таймаут поиска увеличен до 10 секунд.
- Форматирование PSL-части приложения теперь останавливает companion/vendor ELF-процессы, удерживающие `/projects`, но не удаляет ELF-состояние без выбранной области форматирования ELF.

Версия 2.5.0
- Добавлен companion-режим загрузки ELF поверх установленного PSL/LFS-проекта: бинарник запускается рядом с основным проектом, без перевода ПЛК в standalone ELF-режим.
- ZOP теперь загружает ELF payload через companion-сценарий, чтобы не останавливать PSL/LFS runtime и веб-интерфейс ПЛК.
- Добавлена настройка метода загрузки ELF: Companion или Vendor standalone, с краткой справкой по companion-сценарию.
- Добавлена проверка совместимости companion ELF с текущим PSL/LFS-проектом по контракту переменных из load_files.srv.
- Добавлено раздельное форматирование приложения: PSL-часть, ELF-часть или обе области сразу.
- Форматирование при обновлении ядра учитывает выбранные области PSL/ELF.
- Добавлена кнопка чтения информации об установленном проекте на ПЛК: источник загрузки, имя файла, время загрузки, наличие PSL/LFS, companion ELF и vendor standalone ELF.
- При загрузке LFS/ZOP Loader сохраняет metadata проекта на ПЛК для последующего чтения информации.
- Автообновление больше не зависит от ping сервера и сразу проверяет доступность папки с архивами обновлений.
- Улучшена синхронизация UI при включении сборки перед загрузкой: корректно отображается блокировка для PSL в отладочной компоновке.
- Косметические правки интерфейса.

Версия 2.4.8
- Добавлена кнопка открытия веб-интерфейса ПЛК рядом с полем IP-адреса.

Версия 2.4.7
- Добавлено окно настроек, открываемое кликом по иконке приложения в заголовке окна: можно включать/выключать автообновление и выбирать папку с архивами дистрибутива.
- Автообновление больше не выполняет ping сервера и доступ к сетевой папке, если настройка автообновления выключена.

Версия 2.4.6
- После форматирования приложения loader восстанавливает минимальный root-доступ веб-интерфейса ПЛК (`root` / `segnetics`) для отдельного форматирования и обновления ядра с форматированием.

Версия 2.4.5
- Разблокирована возможность отмены операции в процессе обновления ядра.
- Косметические правки.

Версия 2.4.4
- Добавлен механизм автообновления при запуске: loader тихо проверяет доступность `ant-srv`, сравнивает текущую версию с архивом `Segnetics_Loader_v*.zip` во внутренней сетевой папке и предлагает обновление только при наличии новой версии.
- Добавлен отдельный лёгкий updater для framework-dependent дистрибутива: он копируется во временную папку, закрывает loader, показывает этапы загрузки и установки, распаковывает архив поверх текущей папки приложения и запускает обновлённый loader.
- Single-file дистрибутив не содержит updater.

Версия 2.4.3
- Обновление ядра из Rockchip MaskRom теперь не прерывается пользовательской отменой после запуска recovery-последовательности.
- Отдельная операция обновления ядра завершается сразу после успешного завершения recovery-загрузчика, без ожидания DHCP/SSH-подключения, если дальше не запланирована загрузка проекта.
- Recovery-профиль Rockchip отображается по платформе `Rockchip/aarch64` без привязки к конкретной модели ПЛК.

Версия 2.4.2
- При обновлении ядра по USB loader умеет поднимать ПЛК из Rockchip MaskRom recovery: загружает vendor mini-loader/recovery-образ через rkdeveloptool, ждёт появления USB/RNDIS адаптера и продолжает штатный DHCP/TFTP recovery-пайплайн.

Версия 2.4.1
- Добавлен фильтр логов `[WARN]`/`[ERROR]` для окон лога операции и сборки.
- Автоматический режим `A` теперь включает перенос строк и фильтрацию предупреждений/ошибок при ошибках, а на следующей операции сбрасывает только состояния, включённые автоматически.
- Исправлено отображение боковых кнопок управления логами при изменении высоты областей логов.

Версия 2.4.0
- Добавлена поддержка PXL2/Pixel2 в определении ПЛК, проверке совместимости PSL/LFS с подключённым контроллером, fake PLC-сборке и профиле обновления ядра Rockchip.
- Загрузка LFS больше не блокируется из-за отсутствующих или неполных настроек интерфейсов: loader продолжает установку, пишет предупреждение в лог и показывает итоговый статус «Успешно загружено с предупреждениями».
- Добавлено форматирование приложения для PXL2/Pixel2 через общий Rockchip/aarch64 профиль SMH5 с очисткой проектных runtime-файлов.
- При формировании load_files.if DHCP-only Ethernet-записи без адресных полей больше не считаются ошибкой отсутствующего Ethernet-интерфейса на ПЛК.

Версия 2.3.1
- Добавлено автоматическое включение переноса строк в логах при ошибках: настройка включена по умолчанию в новых дистрибутивах и отключается для следующей операции.

Версия 2.3.0
- Fake PLC при сборке PSL -> LFS виртуализирует локальный COM-порт SMLogix, поэтому сборка больше не зависит от наличия физического COM-порта на компьютере и не падает с ошибкой 40043 на машинах без serial-устройств.

Версия 2.2.5
- Fake PLC при сборке PSL -> LFS теперь берёт версии пакетов из установленного `Linux_Kernel\firmware.frw` SMLogix для соответствующего профиля SMH4/SMH5. Если версии не удалось извлечь, сборка останавливается с понятной ошибкой без fallback на искусственные значения.

Версия 2.2.4
- Если SMLogix требует запуск от администратора, loader показывает понятную ошибку запуска SMLogix вместо длинного технического fake PLC failure.
- Сборка PSL -> LFS через fake PLC упрощена: loader больше не запускает настоящий sm_dhcp SMLogix и использует встроенный native DHCP stub без command-monitor/state-прослоек.

Версия 2.2.3
- При ошибке сборки PSL -> LFS loader сохраняет технические логи fake PLC/SMLogix в подпапку `errorlog` рядом с пользовательскими логами и выводит путь к ней в журнал сборки.

Версия 2.2.2
- Профиль форматирования приложения SMH4 упрощён: loader больше не восстанавливает rootfs seed `settings.sqlite`, а сбрасывает `/projects/settings.sqlite` в пустой файл по подтверждённой схеме, аналогичной SMH5.

Версия 2.2.1
- Сборка PSL -> LFS больше не прерывается, если в PSL нет встроенной языковой базы или найден неизвестный `language_id`: loader создаёт `sys/project_languages` как русский по умолчанию и пишет предупреждение в лог сборки.
- Отдельное форматирование приложения на SMH4 теперь очищает runtime-состояние аварий ПЛК: старые аварии и журнал almon не остаются после очистки проекта.

Версия 2.2.0
- Добавлено отдельное форматирование приложения на ПЛК для SMH4: loader очищает проектные файлы, восстанавливает чистую settings.sqlite и перезагружает ПЛК без обновления ядра.
- Формирование load_files.if при загрузке LFS уточнено для состояния после форматирования: если Ethernet-настройки проекта на ПЛК отсутствуют, loader выводит короткое предупреждение и продолжает сборку load_files.if без них.

Версия 2.1.1
- Внутренние сообщения диагностики получили уровни normal, warning и error; предупреждения и ошибки в окнах диагностики и сохраняемых текстовых логах помечаются `[WARN]` и `[ERROR]`.
- Стартовые сообщения операций больше не помечаются как `[WARN]`; предупреждения остаются только для реально предупреждающих событий.
- При формировании `load_files.if` loader больше не запрашивает `get com/mbs` у ПЛК: COM и MBS собираются из проектного `if.json`, а отсутствие Ethernet-интерфейса выводится как предупреждение без остановки загрузки.

Версия 2.1.0
- В полном цикле при разовом сбое этапа сборки loader предлагает повторить только сборку, не перезапуская уже начатое обновление ядра.
- Подробности ошибки сборки теперь сразу попадают в журнал сборки, не дожидаясь завершения всего полного цикла.

Версия 2.0.9
- Сборка PSL -> LFS теперь добавляет языковые файлы проекта `sys/project_languages` и `sys/lang`, чтобы проекты с переводами загружались с корректными текстами.
- При загрузке LFS loader формирует `load_files.if` перед упаковкой `load_files.zip`: берёт проектные настройки из `if.json`, текущие интерфейсы с ПЛК через `iface_settings_from_logix.sh` и не использует готовый `load_files.if` из архива как fallback.

Версия 2.0.8
- Загрузка готовых `.lfs` и `.zop` теперь сверяет тип проекта LFS с подключённым ПЛК и блокирует установку при несовпадении SMH4/SMH5 до передачи `load_files.zip`.

Версия 2.0.7
- Исправлена сборка пустых проектов PSL: пустой `load_files.tss` теперь обрабатывается как штатный payload и не блокирует создание LFS.

Версия 2.0.6
- В полном цикле кнопка загрузки может отменять сборку и последующую загрузку, не прерывая уже начатое обновление ядра.
- После отмены полного цикла итоговый статус учитывает результат обновления ядра: успешное завершение показывает «Ядро обновлено», ошибка обновления остаётся ошибкой.
- В полном цикле окна логов фиксируются в 50/50 и больше не меняют размер от автоматических записей; ручной клик по области лога по-прежнему запускает анимацию.

Версия 2.0.4
- Полный цикл со сборкой теперь до запуска SMLogix сравнивает тип выбранного `.psl` с типом подключённого ПЛК и блокирует сценарий при несовпадении SMH4/SMH5.
- В логи полного цикла добавлен явный тип проекта SMLogix, чтобы mismatch проекта и ПЛК был виден без анализа fake PLC ошибок.
- Для кнопки сборки перед загрузкой добавлено отдельное жёлтое состояние ожидания очереди; красный цвет оставлен только для реальной ошибки сборки.
- Уточнён порядок статусных анимаций полного цикла: загрузочная анимация включается только на фактическом этапе загрузки.

Версия 2.0.3
- Статусная плашка больше не ограничивает ширину текста фиксированным лимитом.
- Перед полным циклом со сборкой loader проверяет связь с ПЛК и не запускает сборку/обновление, если подключение недоступно.
- Проекты `.psl` в отладочной или неизвестной компоновке блокируют полный цикл до запуска сборки и обновления ядра.
- При выборе или перетаскивании `.psl` поле ELF на вкладке сборки очищается, а выходной файл принудительно становится `.lfs`.
- Для этапа подключения добавлена отдельная пиксельная ping-pong анимация в статусной плашке.

Версия 2.0.2
- Для этапа обновления ядра добавлена отдельная пиксельная анимация записи прошивки в статусной плашке.
- Уточнена анимация обновления ядра: фоновая пиксельная сетка скрыта, а волна завершает выход за правый край плашки перед новым циклом.

Версия 2.0.1
- Кнопка форматирования приложения при обновлении ядра теперь показывает зелёный/красный результат этапа вместе с кнопкой обновления ядра.
- Выделение текста в полях IP, SSH-пользователя и пароля приведено к стилю выделения логов.

Версия 2.0.0
- Сборка PSL -> LFS переведена на встроенный .NET fake PLC и нативный x86 TCP-редиректор для SMLogix.

Версия 1.9.17
- Portable-дистрибутив теперь включает готовый Python runtime для fake PLC в виде `tools\python-runtime.7z`: пользователю не нужно устанавливать Python, Frida, Paramiko или pyftpdlib вручную, а размер runtime в папке сборки уменьшен примерно со 160 МБ до 40 МБ.
- При сбое fake PLC во время сборки PSL -> LFS журнал сборки теперь показывает полную техническую диагностику, а статус остаётся коротким.
- Исправлен повреждённый текст подсказки сохранения лога сборки.

Версия 1.9.16
- Кнопка нижнего окна диагностики переименована в «Последние строки лога процесса на ПЛК».
- Добавлен переключатель автопрочтения лога процесса на ПЛК: при включении loader обновляет хвост `/tmp/<name>.log` один раз в секунду и показывает состояние через оранжевый/серый глиф.

Версия 1.9.15
- Сборка PSL -> LFS больше не запускает SMLogix на копии проекта вне папки исходника: теперь создаётся короткая временная ASCII-копия рядом с исходным `.psl`, что сохраняет относительные ресурсы и не изменяет оригинальный проект.
- Перед сборкой очищаются старые рабочие папки SMLogix Exchange и расширена проверка блокирующих процессов SMLogix/kolparser/Translator/sm_dhcp/7za.
- Fake PLC/tracer для SMLogix обновлён: производственный режим не цепляет helper-процессы Translator/kolparser хуками, а при таймауте завершает зависший SMLogix.
- Длинные диагностические сообщения статуса ограничены, чтобы ошибка fake PLC не растягивала нижнюю область окна.

Версия 1.9.9
- В поле «Выходной файл» добавлена кнопка открытия папки выбранного выходного файла.

Версия 1.9.8
- Иконка кнопки «Остановить» заменена на filled stop-sign вариант.
