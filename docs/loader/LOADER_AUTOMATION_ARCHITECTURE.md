# Архитектура Loader Automation

## Назначение

Loader Automation предоставляет фоновый запуск сборки и загрузки проектов без
открытия графического интерфейса. Загрузка использует общий production-runner,
а отдельная сборка PSL использует тот же production-конвертер, что и GUI и
PSL-сценарий загрузки.

Действующий внешний JSONL-контракт описан в `LOADER_AUTOMATION_API.md`.

## Компоненты

| Компонент | Ответственность |
| --- | --- |
| `ProjectDeploymentPlanner` | Проверяет запрос и артефакт, определяет тип проекта и формирует последовательность шагов без обращения к ПЛК. |
| `PlcConnectionResolver` | Разрешает USB/RNDIS или Ethernet-подключение и формирует итоговые SSH-параметры. |
| `ProjectPreparationService` | Выполняет форматирование обеих частей проекта, обновление ядра и восстановление подключения для режима `formatAndUpdateFirmware`. |
| `ProjectDeploymentRunner` | Исполняет построенный план через production-сервисы сборки и загрузки и публикует унифицированные события. |
| `IPslToLfsConverter` | Собирает PSL в заданный LFS через изолированный SMLogix без подключения к ПЛК. |
| `MainViewModel` | Формирует GUI-запрос и отображает события runner в прогрессе, статусе и журнале. |
| `LoaderAutomationHost` | Читает JSONL-запросы, направляет `deploy` в runner, `build` в PSL-конвертер и сериализует события в JSONL. |

Основные типы слоя оркестрации находятся в `SegneticsLoader.Core.Deployment`.
Automation host зависит от Core и не содержит отдельной реализации загрузки.

## Поток выполнения

1. Для `deploy` GUI или Automation формирует `ProjectDeploymentRequest`.
2. `ProjectDeploymentPlanner` проверяет путь, сигнатуру и допустимость входного
   файла, после чего создаёт `ProjectDeploymentPlan`.
3. При выбранной подготовке `ProjectPreparationService` форматирует проект,
   обновляет ядро и ожидает восстановления ПЛК.
4. `PlcConnectionResolver` определяет рабочее подключение и SSH-параметры.
5. `ProjectDeploymentRunner` выполняет шаги плана и передаёт события прогресса,
   журнала и результата вызывающей стороне.
6. Для `deploy` PSL с заданным `outputPath` runner после успешной загрузки
   атомарно сохраняет собранный LFS во внешний каталог.
7. Операция завершается единственным терминальным результатом: успешно,
   ошибка или отмена.

Для `build` Automation проверяет PSL и выходной путь, получает общую блокировку
Loader, при необходимости синхронизирует изолированный SMLogix и вызывает
`IPslToLfsConverter`. Resolver подключения, подготовка ПЛК и deployment runner в
этом сценарии не запускаются. Если выходной путь не задан, используется LFS
рядом с исходным PSL; перезапись включена по умолчанию.

## Сценарии артефактов

| Артефакт | Последовательность |
| --- | --- |
| PSL | Изолированная сборка PSL в LFS, загрузка полученного LFS и опциональное сохранение результата в `outputPath`. |
| LFS | Прямая загрузка LFS. |
| ZOP | Извлечение контейнера, загрузка LFS, ожидание готовности проекта и загрузка вложенного ELF в companion-режиме. |
| ELF без расширения | Проверка ELF и выбор режима загрузки по runtime metadata и сохранённой legacy-настройке Loader. |

Проверка входного артефакта выполняется до подключения к ПЛК. Неизвестный,
повреждённый или неоднозначный вход завершает операцию стабильной ошибкой.

## Настройки подключения

GUI передаёт resolver текущие значения полей интерфейса. Automation читает
параметры подключения, путь к прошивке и настройки режимов из
`%LOCALAPPDATA%\SegneticsLoader\settings.json`.

Учётные данные остаются внутри Loader и не передаются через командную строку,
запросы или события Automation.

## Конкурентный запуск

GUI и Automation используют общий `LoaderOperationLock`. Одновременно может
выполняться одна операция, использующая ПЛК или SMLogix. Конкурирующий запрос
Automation завершается ошибкой `LOADER_BUSY`.

Automation также ведёт общий маркер состояния операции и сохраняет запрос,
события, результат и технические журналы в каталоге операции. Формат и
расположение файлов описаны в `LOADER_AUTOMATION_API.md`.

## Состав дистрибутивов

`SegneticsLoader.Automation.exe` включается в framework-dependent дистрибутив.
Single-file дистрибутив содержит автономный GUI-вариант Loader.
