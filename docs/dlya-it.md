# Antarus ПО Finder — что нужно от ИТ

Настольное приложение под Windows. Каталог прошивок/параметров/схем/инструкций на сетевых дисках
предприятия, вход по учётной записи, роли, работа даже когда сети временно нет.

Репозиторий: **https://github.com/IlyaRevkin/antarus-po-finder-dotnet**

Ниже по каждому пункту: **сделано** (на нашей стороне) → **нужно от ИТ** → **что в итоге**.

---

## 1. Вход по доменной учётной записи (AD)

**Сделано.** Три способа проверки пароля, выбираются настройкой: напрямую у контроллера домена
(LDAP), через веб-адрес с NTLM/Negotiate, и комбинированно (сначала домен, при недоступности —
веб). Роль (администратор/программист/наладчик) — по членству в группах.
Файлы: `AntarusPoFinder.Core/Services/` — `AdIdentityProvider.cs`, `LdapAdCredentialValidator.cs`,
`HttpAdCredentialValidator.cs`, `CombinedAdCredentialValidator.cs`, `RoleFromGroups.cs`.

**Нужно от ИТ.** Ничего сверх обычного доступа в домен. Если хотите роли по группам — назвать
группы для трёх ролей (можно позже, задаётся в настройках). Для веб-способа — адрес, умеющий
проверить доменный пароль.

**В итоге.** Вход теми же логином и паролем, что и в Windows. Работает уже сейчас.

---

## 2. Единый вход (Keycloak / OpenID Connect)

**Сделано полностью.** Вход в системном браузере, PKCE, разбор токена, роль по группам из токена.
Пароль через программу не проходит. Адреса не зашиты — берутся у сервера по
`.well-known/openid-configuration`. Файл: `AntarusPoFinder.Core/Services/OidcIdentityProvider.cs`.

**Нужно от ИТ.** Поднять OIDC-провайдер и создать клиента:
- тип **публичный** (без секрета), **PKCE S256** обязательно;
- Redirect URI: `http://127.0.0.1/*`;
- добавить в токен claim со списком групп пользователя.
Прислать три строки: **issuer** (`https://хост/realms/<realm>`), **client_id**, **имя claim групп**
(по умолчанию ждём `groups`). Полная спецификация — `docs/keycloak-setup.md` в репозитории.

**В итоге.** Единый вход со вторым фактором. Администратор вводит три строки в программе **один раз**,
и они расходятся на все машины через сетевой диск. По коду безопасно: секрета в программе нет,
`127.0.0.1` снаружи недоступен, MFA работает.

## 3. Диск с данными — транспорт (WebDAV / SMB / FTP / свой сервер)

Ключевой факт: программа работает с диском как с **обычной папкой Windows** (буква диска, файловые
операции). Всё, что монтируется буквой, работает без единой правки в коде.

| Вариант | Правки в коде | Веб-ссылка для QR | Скорость | Вывод |
|---|---|---|---|---|
| **WebDAV** (сейчас) | нет | есть (тот же сервер отдаёт HTTP) | медленно | работает, но тормозит на больших каталогах |
| **SMB** (обычная шара) | нет | нет — нужен отдельный HTTP поверх той же папки | быстро | **лучший под прошивки** |
| **FTP** | **переписывать всё** — Windows не монтирует FTP как диск, `System.IO` его не видит | нет | — | **не рекомендуется** |
| **Свой сервер (WebSocket/HTTP)** | много, отдельный проект | есть, лучшая | — | правильный конечный пункт, но месяцы |

**Сделано.** Работа с диском через файловые операции (любой смонтированный буквой транспорт).
Обмен по умолчанию идёт через файловую шару (`AntarusPoFinder.Core/Services/FileShareTransport.cs`,
`AntarusPoFinder.App/Services/ConfigSyncService.cs`). Рядом появилась вторая реализация того же
интерфейса — по HTTP (`HttpSyncTransport.cs`), а к ней своя служба, см. пункт 6.
**WebSocket-обмена нет** и в ближайшее время не будет: он нужен только чтобы не опрашивать маркер
ревизии, а не для передачи файлов.

**Авторизация на шаре.** Если ставите логин/пароль или сертификат на WebDAV/SMB — Windows
монтирует диск с этими данными, программа дальше просто пользуется буквой. То есть авторизацию на
шаре настраиваете вы на уровне подключения диска, в программе для этого ничего не меняется.

**Нужно от ИТ (выбрать одно).**
- Оставить WebDAV — ничего не нужно, работает.
- **Перевести на SMB** (рекомендуем под прошивки — быстрее и надёжнее на больших каталогах): дать
  SMB-шару, смонтировать её той же буквой. Отдельно для QR-этикеток на инструкции — поднять
  read-only HTTP поверх папки инструкций (можно на третьем диске), чтобы ссылка открывалась
  телефоном.
- FTP — только если принципиально; предупреждаем: это переписывание всей работы с диском.

**В итоге.** Быстрый диск для прошивок + рабочие QR-ссылки на инструкции. Авторизация на шаре —
ваша, программа её не касается.

## 4. Обновление программы

**Сделано.** Два источника: сетевая папка обновлений (приоритет) и GitHub (запас). Путь к папке
задаётся один раз и расходится на все машины; в относительном виде («Обновления») разворачивается от
корня диска, поэтому разные буквы у машин не мешают.
Файлы: `AntarusPoFinder.Core/Services/UpdateFolderResolver.cs`, `AntarusPoFinder.App/AppUpdateService.cs`.

**Нужно от ИТ.** Только если исходящий трафик ограничен списком IP: тогда GitHub из списка выпадет
(у него нет фиксированных адресов) — заведите сетевую папку обновлений, и интернет для обновлений не
понадобится вовсе.

**В итоге.** Обновления доезжают без интернета, из папки на диске.

---

## 5. Фильтрация исходящих по списку IP — оговорка

Если ограничиваете исходящие адреса — в список должны попасть: адрес OIDC-сервера (иначе вход не
работает), адрес веб-проверки пароля (если используете HTTP-способ), веб-адрес диска инструкций (для
QR с телефона). Обновления от внешних адресов не зависят, если настроена папка (п. 4).

## 6. Служба обмена каталогом для машин вне сети

**Сделано.** Служба Windows `antarus-sync` — один файл, ~10 МБ, без .NET и без каких-либо runtime.
Она возит между машинами **каталог** прошивок (маркер ревизии и снимок общего конфига), а не сами
файлы: без общего конфига машина снаружи не узнаёт о новых прошивках вовсе, сколько файлов ей ни
дай. Три ручки, ключ в заголовке, только GET и POST.

Полная инструкция по установке, ключам, порту и публикации — `tools/sync-server/README.md` в
репозитории, там же лежит сам `antarus-sync.exe` с контрольной суммой.

**Нужно от ИТ.** Поставить службу на сервер, который виден снаружи, и решить, как её публиковать:
либо она сама слушает HTTPS (нужен сертификат рядом), либо слушает `127.0.0.1:8443`, а наружу её
отдаёт уже имеющийся IIS/nginx — тогда сертификат остаётся там, где им и так занимаются. Открыть
порт (по умолчанию 8443).

Если нужен доступ и к **самим файлам** прошивок — отдельно есть настройка SFTP поверх встроенного
в Windows OpenSSH, только на одну папку, без терминала и без проброса портов:
`tools/openssh-server/README.md`.

**В итоге.** Наладчики вне корпоративной сети видят актуальный каталог прошивок. Сегодня они не
видят его никак: сетевой диск до них не дотягивается.

⚠️ Честно про ограничение: снимок конфига перезаписывается целиком, поэтому право записи выдаётся
не всем и по умолчанию его нет. Двое пишущих одновременно всё ещё могут затереть работу друг друга
— защита от этого (`reject_stale_revision`) в службе есть, но включается отдельно и осознанно.

## Если хотите править сами (PR)

Репозиторий публичный. Два условия, иначе правка не доедет до людей:
1. **Поднять версию** в `AntarusPoFinder.App/AntarusPoFinder.App.csproj` (`<Version>`) — автообновление
   срабатывает только на строго большей версии.
2. PR отдельной веткой, не в `master` напрямую.
По-хорошему не нужно: всё, что зависит от вашей инфраструктуры (адреса, клиент, группы, транспорт),
вынесено в настройки программы, а не в код.
