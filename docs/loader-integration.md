# Интеграция с Segnetics Loader

## Назначение

Searcher выполняет интерактивную загрузку проектов в ПЛК через локальный
process API `SegneticsLoader.Automation.exe --stdio`. Окно Segnetics Loader не
открывается: Searcher показывает параметры, прогресс и журнал операции, а
production-пайплайн Loader определяет тип файла и выполняет требуемые действия.

Сценариев два:

1. `Загрузить в ПЛК` на карточке версии — заливка (`deploy`);
2. сборка `.psl` → `.lfs` без ПЛК (`build`) — кнопка `Собрать LFS из PSL` в
   модерации прошивки и предложение сразу после выкладки версии с одним
   исходником (см. «Автоконвертация PSL → LFS»).

## Окно операции

Окно компактное и запускается САМО: файл уже выбран карточкой, второе нажатие
«Загрузить» ничего не решало.

- имя файла показано подписью, полный путь — в подсказке при наведении;
- «Дополнительно» — сменить файл, галка подготовки ПЛК, «Запустить заново»;
- строка подготовки ПЛК видна всегда: авто-старт применяет ЗАПОМНЕННОЕ значение
  галки, и оператор обязан видеть его до и во время работы;
- «Подробности» — журнал операции, раскрывается сам при ошибке;
- внизу максимум две кнопки: `Остановить` во время работы, `Закрыть` после;
  рабочая папка и сохранение журнала — в меню `…`, доступном только по итогу;
- недоступность Automation показывается сообщением ДО открытия окна
  (`LoaderDialog.EnsureAvailable`).

## Выбор файла

Карточка представляет версию ПО, поэтому Searcher проверяет артефакты этой
версии в порядке `LFS -> PSL`:

| Файлы версии | Действие |
|---|---|
| Только LFS | Открыть диалог с готовым LFS |
| Только PSL | Открыть диалог с PSL; Loader соберёт LFS и загрузит его |
| LFS и PSL | Открыть диалог с готовым LFS |

Внутри каждого типа выбирается файл, указанный оператором в модерации
(`FwVersionRecord.ExecutableHint`), а не первый попавшийся: в папке версии
бывает пачка `.lfs` (по одному на шкаф). Подсказка применяется только к своему
расширению. Путь можно заменить вручную в блоке «Дополнительно».

## Автоконвертация PSL → LFS

Цель: программист выложил `.psl` — наладчик на ДРУГОЙ машине при поиске уже
видит `.lfs`. Поэтому собранный файл всегда уезжает в папку версии на сетевом
диске, а не только в локальный кэш собравшей машины.

| Момент | Что происходит |
|---|---|
| Выкладка новой версии | Если в папке версии есть `.psl` и нет `.lfs`, Searcher предлагает собрать сразу (нужен установленный изолированный SMLogix; иначе — подсказка собрать позже в модерации) |
| Модерация прошивки | Кнопка `Собрать LFS из PSL` — там же, где докладывают файлы прошивки; видна, только когда собирать есть что и есть куда положить |
| Заливка в ПЛК | Собранный по ходу `deploy` LFS публикуется туда же (папка версии на диске + локальная копия) |

Правила публикации (`LfsPublisher`, `LfsConversionService`):

- сборка идёт локально в `LoaderWorkspace`, на диск уезжает только готовый файл;
- файл сначала копируется под именем `*.lfs.part` и лишь потом одним
  переименованием занимает место целевого — обрыв шары оставляет мусорный
  `.part`, но не битый `.lfs`;
- исходник для сборки берётся с сетевого диска, а не из локального кэша: иначе
  рядом с сетевым `.psl` лёг бы `.lfs`, собранный из устаревшей копии;
- сетевая папка недоступна — сборка не запускается (класть результат некуда);
  при заливке в ПЛК это лишь предупреждение: прошивка в контроллере уже есть.

## Подготовка ПЛК

Единственная опция Searcher называется `Форматировать проект и обновить ядро`.
Она передаётся в запрос Automation атомарно:

| Состояние | `preparation` |
|---|---|
| Выключено | `none` |
| Включено | `formatAndUpdateFirmware` |

Адрес ПЛК, режим подключения, SSH-параметры и путь к прошивке Searcher не
передаёт. Automation читает их из настроек Segnetics Loader:

```text
%LOCALAPPDATA%\SegneticsLoader\settings.json
```

## Поиск Automation

Настройка Searcher может содержать:

1. пустое значение: используется
   `<папка Searcher>\Loader\SegneticsLoader.Automation.exe`;
2. папку Segnetics Loader: Automation ищется внутри неё;
3. путь к `SegneticsLoader.exe`: Automation ищется рядом с GUI;
4. путь к `SegneticsLoader.Automation.exe`: используется этот файл.

Если Automation отсутствует, Searcher показывает точный ожидаемый путь и не
подменяет операцию заглушкой или запуском GUI.

## Выполнение операции

1. Searcher создаёт рабочую область в
   `%LOCALAPPDATA%\AntarusPOFinder\loader\<operation>`.
2. Выбранный файл копируется в подпапку `src`.
3. Searcher запускает `SegneticsLoader.Automation.exe --stdio`.
4. В stdin передаётся запрос `deploy` (или `build` для отдельной сборки) с
   локальным путём. Для PSL также задаётся `outputPath` в подпапке `out`
   рабочей области; в запросе `build` поле `preparation` не передаётся.
5. Loader собирает и загружает PSL, затем сохраняет готовый LFS в `outputPath`
   до отправки события `completed`.
6. Searcher после `completed` публикует готовый LFS в папку версии на сетевом
   диске и в локальную копию той же версии. При следующей загрузке он выбирается
   раньше PSL — в том числе на других машинах.
7. События `started`, `plan`, `progress` и `log` обновляют прогресс и журнал.
8. `completed`, `failed` или `cancelled` завершает операцию в диалоге.
9. Кнопка `Остановить` передаёт JSONL-команду `cancel` в тот же процесс.

Лог Searcher сохраняется в рабочей области. Технические логи Loader находятся
в каталоге, указанном полем `error.logDirectory` события `failed`.

## Границы ответственности

Searcher отвечает за выбор версии, выбор LFS с резервным переходом к PSL с
учётом выбранного в модерации файла, локальную копию файла, публикацию успешно
собранного LFS в папку версии на диске и отображение хода операции. Segnetics Loader отвечает за распознавание артефакта,
сборку PSL, сохранение результата в локальную рабочую область Searcher,
подключение к ПЛК, форматирование, обновление ядра и загрузку.

Исходный код Loader в репозиторий Searcher не копируется. Инсталлятор Searcher
содержит опубликованный framework-dependent runtime Loader без локального
каталога `SMLogix isolated payload`. Перед изолированной сборкой Loader сам
проверяет и при необходимости синхронизирует этот каталог из установленного
SMLogix. Для Automation требуется установленный Microsoft .NET 8 Runtime x64.
