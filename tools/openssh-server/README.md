# OpenSSH на сервере: доступ снаружи к одной папке

Инструкция для ИТ. Даёт людям вне корпоративной сети доступ **только к одной папке** и **только по
SFTP** — без рабочего стола, без доступа к остальному диску, без пароля.

Это дополнение к службе обмена `antarus-sync` (см. `tools/sync-server/`), а не замена: та возит
**каталог** прошивок, эта — **сами файлы**.

## Что ставится

OpenSSH Server входит в состав Windows Server 2019/2022 и Windows 10/11 как встроенный компонент —
скачивать ничего не нужно. Проверено на сборке `OpenSSH_for_Windows_9.5p2`: директивы
`Match Group`, `ChrootDirectory` и `ForceCommand internal-sftp` она принимает (`sshd -t` проходит).

## Установка

От администратора, в папке со скриптами:

```powershell
.\setup-sftp.ps1
```

По умолчанию: папка `C:\AntarusShare`, группа `antarus-sftp`, порт 22, проброс портов запрещён.
Меняется параметрами:

```powershell
.\setup-sftp.ps1 -ShareRoot 'D:\Antarus\Обмен' -Port 2222 -Group 'antarus-sftp'
```

Скрипт идемпотентный: повторный запуск не задваивает блоки в конфиге и не ломает уже выданные
доступы. Перед правкой `sshd_config` делается резервная копия, а перед перезапуском службы конфиг
проверяется через `sshd -t` — если он некорректен, служба не трогается.

## Выдать человеку доступ

Человек присылает **открытый** ключ (файл `.pub`). Закрытый остаётся у него и никуда не передаётся.

```powershell
.\add-sftp-user.ps1 -User naladchik1 -PublicKeyFile C:\Temp\naladchik1.pub
```

Скрипт заводит локальную учётку, включает её в группу, кладёт ключ и создаёт личную папку внутри
`Обмен`. Перезапускать службу не нужно.

Отобрать доступ:

```powershell
.\add-sftp-user.ps1 -User naladchik1 -Remove
```

Учётка при этом отключается, но не удаляется — чтобы осталась видна история, кому выдавали.

Ключ человек создаёт у себя одной командой:

```powershell
ssh-keygen -t ed25519 -C "naladchik1@antarus"
```

Прислать надо содержимое `.pub`, файл без расширения — закрытый, его не пересылают.

## Как это выглядит у пользователя

```
sftp naladchik1@адрес-сервера
```

Или мышью: WinSCP / FileZilla, протокол SFTP, вход по ключу. Он видит корень как `/`, внутри —
папку `Обмен` со своей личной папкой. Выйти выше корня нельзя, остального диска не существует.

## Что именно запрещено и почему

Блок в `sshd_config`:

```
Match Group antarus-sftp
    ChrootDirectory C:\AntarusShare
    ForceCommand internal-sftp
    AllowTcpForwarding no
    PermitTunnel no
    X11Forwarding no
    AllowAgentForwarding no
    PermitTTY no
```

- `ChrootDirectory` — выше этой папки пользователь не поднимется.
- `ForceCommand internal-sftp` — только передача файлов. Команду выполнить нельзя, даже если
  попросить её явно при подключении.
- `AllowTcpForwarding no` — **это важно**: проброс портов даёт доступ к любым внутренним адресам,
  которые видит сервер. Тот, кому выдали папку, иначе получил бы вход во всю сеть. Включается
  осознанно и отдельно: `setup-sftp.ps1 -AllowPortForwarding`.
- `PermitTTY no` — нет терминала.

Блок `Match` обязан быть **последним** в файле: всё, написанное после `Match`, относится к нему, а
не к общим настройкам. Скрипт дописывает его в конец, но если ИТ правит файл руками — дописывать
что-либо ниже нельзя.

## Две подножки Windows-сборки

Обе стоят полдня разбирательств, поэтому вынесены отдельно.

**1. Права на папку chroot.** Корень chroot и все папки выше него должны принадлежать
администратору/SYSTEM и не быть доступны на запись обычным пользователям. Иначе подключение
обрывается без внятного сообщения, а в журнале — `bad ownership or modes`. Поэтому раскладка
такая: корень только на чтение, писать можно во вложенную `Обмен`. Скрипт это уже выставляет.

**2. Ключи администраторов лежат не там.** Для членов группы «Администраторы» файл
`authorized_keys` в профиле **игнорируется** — читается общий
`C:\ProgramData\ssh\administrators_authorized_keys`. Наши SFTP-пользователи администраторами быть
не должны; если случайно сделать пользователя администратором, вход по ключу перестанет работать
без единого сообщения.

**3. Если будете править сами скрипты — сохраните BOM.** Оба `.ps1` в этой папке содержат
кириллицу и сохранены в UTF-8 **с BOM**. Windows PowerShell 5.1 читает `.ps1` без BOM как ANSI:
русский текст превращается в мусор, и скрипт перестаёт разбираться ещё до запуска — с ошибками,
которые на настоящую причину не намекают вовсе. Блокнот и VS Code сохраняют BOM, если он был; PowerShell ISE — тоже.

## Вход по паролю

Оставлять его наружу не стоит: пароль от локальной учётки сервера, гуляющий по переписке, — ровно
то, чего мы избегаем. В `sshd_config`:

```
PasswordAuthentication no
```

Скрипт эту строку **не** трогает, потому что она общая для всего сервера и может задеть другие
подключения. Решение за ИТ.

## Порт и публикация

По умолчанию 22. Правило брандмауэра скрипт добавляет сам. Если 22 наружу отдавать не хочется,
берите другой порт: `-Port 2222` — скрипт поправит и конфиг, и правило.

## Проверка после установки

```powershell
Get-Service sshd
Get-LocalGroupMember -Group antarus-sftp
C:\Windows\System32\OpenSSH\sshd.exe -t -f C:\ProgramData\ssh\sshd_config
```

Журнал подключений и отказов:

```powershell
Get-WinEvent -LogName 'OpenSSH/Operational' -MaxEvents 50 | Format-Table TimeCreated, Message -Wrap
```

## Про «проброс портов»

Проброс портов и доступ к папке — разные вещи, и стоит развести их явно.

**Доступ к папке** — то, что описано выше: SFTP с ограничением на одну папку.

**Проброс портов** — это когда через SSH-соединение пробрасывается TCP-порт: подключившийся
получает доступ к внутреннему адресу, видимому серверу. Может пригодиться, чтобы дотянуться до
службы обмена `antarus-sync`, не публикуя её наружу отдельно.

Но для программы это плохой путь: каждому клиенту пришлось бы держать поднятый SSH-туннель, а
Finder про туннели ничего не знает — он ходит по адресу из настроек. Проще опубликовать службу на
её порту (8443) и не заводить второй механизм. Поэтому проброс по умолчанию запрещён, и включать
его стоит только под конкретную задачу.
